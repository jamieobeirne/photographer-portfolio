### Root causes worth remembering

- **#15** was a case-sensitivity bug. `3avopcuxv10` vs `3AvopCUxv10`. It was the
  only all-lowercase 11-char ID in the codebase — a useful grep if another video
  dies.
- **#16** playlists embed as `/embed/videoseries?list=…`, which has no video ID, so
  `getThumbnailUrl` returned `null`. Fixed by embedding as `/embed/<cover>?list=<id>`.
  Also: a deleted/private YouTube video returns HTTP 200 from `i.ytimg.com` with a
  120×90 grey image, so dead videos and playlists looked identical. `VideoGrid` now
  treats a ≤120px-wide response as missing.
- **#18** the mobile menu was never missing. `PageHero` is `justify-between`, the
  logo was `shrink-0` and `h-[4.75rem]` (taller than its own `sm` step), so it ate
  the row and pushed the hamburger past `overflow-hidden`.
- **#24** `projectForMedia` fell back to `{ project: serviceTag }` and
  `ServiceGalleryPage` suppressed the heading for exactly that value — hence an
  unlabelled pile at the end of Publicidad. Now `UNGROUPED_PROJECT`, rendered as
  "OTRAS FOTOS". **This bucket is load-bearing:** photos Nahuel uploads by hand
  through WP admin cannot match the `<tag>-drive-<id>-<name>` slug the importer
  writes, so they land there by design. Do not "fix" it by dropping them.
- **Bio drift.** The prose was hardcoded twice per persona — `/biografia` and the
  section home — and had already diverged (18 vs 17 years). All six surfaces now
  import from `lib/bios.ts`, synced to Nahuel's three Google Docs.

## Sandbox constraints (matters for any future cloud session)

The Cowork cloud container has **no outbound route** to:

- `lightcyan-deer-205982.hostingersite.com` — so no WP reads or writes
- `youtube.com` / `vimeo.com` — so no video liveness testing
- `fonts.googleapis.com` — so `next build` fails at `next/font/google` in `layout.tsx`

The desktop workspace VM (`device_bash`) has **no network at all**, and cannot
delete files.

Workaround used for verification: temporarily stub the `Jost` import in
`app/layout.tsx`, run `next build` (passes, all 23 routes prerender), start
`next start`, screenshot with the pre-installed Chromium at
`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, then restore. Pages render
because every WP fetch is inside `try {} catch {}` and falls back to placeholders.

Consequence: layout, spacing and type can be verified in the cloud. **Anything
image-dependent cannot** — including #18, which needs the real logo to reproduce.
Those checks have to happen on Jamie's machine with `npm run dev`.
